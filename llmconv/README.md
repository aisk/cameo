# llmconv

Package `llmconv` converts requests and replies between four LLM wire
protocols:

| Constant            | Protocol                       |
| ------------------- | ------------------------------ |
| `llmconv.Chat`      | OpenAI Chat Completions        |
| `llmconv.Responses` | OpenAI Responses               |
| `llmconv.Anthropic` | Anthropic Messages             |
| `llmconv.Gemini`    | Google Gemini generateContent  |

Every conversion goes through one intermediate form. A request body is parsed
into a `Request` and built again for another protocol. A streamed reply is
decoded into `Event` values, which are either encoded as another protocol's
server-sent events or collected into a `Result` and rendered as a whole reply
body.

It depends on the standard library and `github.com/tidwall/gjson`.

## Usage

```go
import "github.com/aisk/cameo/llmconv"

// The client sent an Anthropic Messages request; the upstream speaks Chat.
func handle(w http.ResponseWriter, body []byte) error {
	req, err := llmconv.Parse(llmconv.Anthropic, body)
	if err != nil {
		return err
	}
	stream := req.Stream
	req.Stream = true // replies are only read as streams, see Limits
	out, err := llmconv.Build(llmconv.Chat, req, "gpt-4o", llmconv.BuildOptions{Host: "api.openai.com"})
	if err != nil {
		return err
	}

	res, err := http.Post("https://api.openai.com/v1/chat/completions", "application/json", bytes.NewReader(out))
	if err != nil {
		return err
	}
	defer res.Body.Close()
	// (set the Authorization header and check res.StatusCode in real code)

	if stream {
		return llmconv.ConvertStream(llmconv.Chat, llmconv.Anthropic, res.Body, w, req)
	}
	reply, err := llmconv.ConvertResponse(llmconv.Chat, llmconv.Anthropic, res.Body, req)
	if err != nil {
		return err
	}
	w.Header().Set("Content-Type", "application/json")
	_, err = w.Write(reply)
	return err
}
```

`ConvertRequest` does the parse and build in one call when the request does
not need to be looked at in between. `NewDecoder`, `NewEncoder`, `Collector`,
`Render` and `ReadSSE` are the pieces `ConvertStream` and `ConvertResponse`
are made of, for callers that want to see or change the events on the way.

## Where the code comes from

Most of this package is generated from the gateway of
[magpie](https://github.com/yetone/magpie) (MIT, see `LICENSE-magpie`), which
translates between these protocols as part of a larger local gateway. Files
that start with `// Code generated by llmconv/internal/sync` are copies of
upstream declarations and must not be edited. The revision they were taken
from is in `UPSTREAM`.

Written by hand: `llmconv.go` (the exported API), `example_test.go`,
`internal/provider/shim.go` (stand-ins for two upstream functions that read
account state) and the generator itself.

To resync, from the root of this repository:

```sh
go run ./llmconv/internal/sync /path/to/magpie
go build ./llmconv/... && go vet ./llmconv/... && go test ./llmconv/...
```

The generator's `targets` table in `internal/sync/main.go` lists, for each
upstream file, whether it is taken whole, without some declarations (`drop`),
or only some (`keep`). When upstream starts using a symbol the table does not
carry, the build fails with it undefined: add it to the table if it is pure
encoding or decoding, and otherwise drop the declaration that needs it or add
a stand-in to a `shim.go`. Upstream tests that need no server or provider are
carried the same way.

## Limits

- Replies are read as streams only. There is no parser for a non-streamed
  upstream reply body, so ask the upstream to stream and use
  `ConvertResponse` when the client wants a whole reply.
- This is the encoding and decoding only. What magpie does around it in its
  gateway is not here: choosing a provider or model, sending the request,
  authentication, retries and fallbacks, rewriting a request after an
  upstream refuses it with a 400, continuing a reply that was cut off,
  treating an empty reply as a failure, turning tool calls a model wrote as
  text into calls, running web search on a model's behalf, counting tokens,
  timed keepalives, and the fix-ups it applies to bodies it passes through
  without translating.
- What a protocol can say that the intermediate form cannot hold is lost in
  conversion.
- `BuildOptions.Host` is how the builders recognise a vendor's quirks. With
  it empty a request is built plainly, which some vendors refuse (see its
  documentation).
- A Gemini request names its model and whether it streams in the URL, not
  the body. `Parse` reads top-level `model` and `stream` fields when a body
  has them and otherwise leaves both unset: set `Request.Model` and
  `Request.Stream` yourself. A body built for Gemini carries a `model`
  field, as upstream sends it, and the caller still chooses the URL.
- Google Code Assist (the Gemini CLI and Antigravity account API) is not
  supported as a protocol, though the Gemini builder shares code with it.
- The exported names and behaviour follow upstream, which changes often and
  makes no compatibility promise; a resync can change either.
